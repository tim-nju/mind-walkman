# 心智随身听 · 技术架构与设计

> **项目定位**：上下班通勤随身听应用。专门用于收听、精读、反复推敲和内化提炼出的长篇深度人生与商业智慧分享。
> **选型铁律**：零苹果开发者账号依赖（$0 年费），原生 JS PWA 架构，离线优先，全量锁屏与耳机控制支持。

---

## 目标与范围

### 1. 核心目标
- **通勤沉浸听**：支持在手机锁屏、放在口袋、使用耳机线控（暂停/播放、快进快退）的情况下稳定连续播放。
- **高频精听与内化**：针对经典分享，支持单曲死循环、A-B 区间反复精听推敲、0.8x～2.0x 无级/快捷倍速。
- **图文音联动**：章节时间戳与深度提炼金句卡片联动，点击任意要点秒跳音频对应位置；播放进度实时高亮当前章节。
- **真·离线可用**：首期音频与文本通过 Service Worker 预缓存于本地，在地铁弱网或飞行模式下秒开收听。

### 2. 边界约束
- **不依赖 iOS 开发者账号**：不采用原生 Swift 或 Flutter 真机打包，杜绝每 7 天重签证书问题。
- **自用优先、零运维负担**：静态单页架构，不引入庞大 Node 运行时或付费后端服务。

---

## 技术栈

| 层次 | 选型 | 决策理由与历史依据 |
| :--- | :--- | :--- |
| **前端展现** | 原生 HTML5 / CSS3 / ES6+ | 零打包构建工具，原生运行性能最高，启动速度毫秒级 |
| **应用形态** | PWA (Progressive Web App) | 符合《项目技术栈总览》既有成功经验（日课、当下），Safari 一键“添加到主屏幕” |
| **离线缓存** | Service Worker + CacheStorage API | 静态资源与大体积音频离线固化，断网即用 |
| **音频引擎** | HTML5 Audio + Web Audio API | 原生解码，耗电低，后台播放资源占用极小 |
| **系统级交互** | MediaSession API (`navigator.mediaSession`) | 支持 iOS/macOS 锁屏大封面、歌曲名、讲者、耳机按键线控与进度控制 |
| **存储扩展** | 本地 IndexedDB / LocalStorage | 存储播放进度、A-B 复读标记点、自定义笔记与倍速记忆 |

### 2. 播放状态模型（PlaybackState）
- `lastTrackId`: 记录上次播放的音轨 ID
- `currentTime`: 上次播放中断的时间戳（秒），用于下次无缝断点续播
- `playbackRate`: 偏好播放倍速（默认 1.0，可选 0.8 / 1.25 / 1.5）
- `repeatMode`: 循环模式：`one`（单曲循环）、`all`（列表循环）、`ab`（A-B区间循环）
- `abPoints`: `{ a: number | null, b: number | null }`

## 接口与契约

### 1. 系统锁屏与线控契约（MediaSession API）
前端向操作系统注册 `MediaMetadata` 及事件监听器：
- `play` / `pause`：系统和耳机线控的播放与暂停
- `seekbackward`：步退 15 秒（通勤防漏听）
- `seekforward`：步进 30 秒
- `previoustrack` / `nexttrack`：上下一章节跳转
- `seekto`：进度条拖动与位置同步

### 2. Service Worker 离线网络拦截契约
- `install` 事件：预缓存核心 Shell 资源（HTML、CSS、JS、Manifest、图标）
- `fetch` 事件：
  - 核心静态资源优先命中 CacheStorage（Cache-First）；
  - 音频大文件采用 Range 请求适配与本地缓存回落，确保 Safari 流式播放无缝解码。

## 关键流程

### 1. 首次加载与离线预热流程
1. 页面加载 `index.html`，主线程注册 `sw.js`；
2. Service Worker 在后台预拉取静态资源与专辑元数据；
3. 用户首次点击播放音频时，音频流一边播放一边由 CacheStorage 固化，实现后续全离线秒开。

### 2. 章节点击与播放定位流程
1. 用户在金句列表点击某章节（例如 `[20:14] 认知觉醒`）；
2. 播放器接收事件，设置 `audio.currentTime = 1214` 并触发 `audio.play()`；
3. 界面滚动将该章节高亮卡片居中，同时更新锁屏界面的章节信息。

### 3. A-B 区间复读循环流程
1. 播放到关键金句时点击【设置 A 点】，记录起始时间；
2. 听完金句点击【设置 B 点】，播放器进入 A-B 复读循环模式；
3. `timeupdate` 监听当前时间超过 B 点时，无缝 `seek` 回 A 点继续播放；点击取消则恢复常规播放。

## 安全与隐私

- **纯本地数据留存**：所有播放进度、复读标记、自定义笔记均保存在客户端浏览器 LocalStorage/IndexedDB 中。
- **无第三方统计与埋点**：没有任何外部追踪 SDK、广告分析或用户隐私采集，完全离线自用。
- **音频物理隔离**：音频直接存放在自用 iCloud / 本地目录，不向未授权公网 CDN 泄露个人录音。

## 技术决策

- **决策 001**：选用原生 JS PWA 架构。根据《项目技术栈总览》和用户明确意图，不采用需支付 $99/年开发者账号的原生 iOS/Flutter 打包，采用完全免费、离线可控的 PWA 技术。
- **决策 002**：音频采用未降噪的现场原声完整版。过度降噪会严重损伤人声基频与共鸣，原声更耐听、保真度最高。
- **决策 003**：采用无构建（Zero-Build）原生 ES 模块。页面不依赖 Webpack/Vite 复杂打包链路，确保代码在任何环境下开箱即用，维护成本降至最低。
- **决策 004**：针对 iOS Safari 离线播放采用 IndexedDB 闪存持久化 + Service Worker Range 请求双层保障。用户点击【📥 离线缓存】时使用流式读取器（ReadableStream）实时反馈下载进度，将 52.8MB 完整音频持久化到本地 IndexedDB；播放时转为本地 ObjectURL，彻底规避 iOS Safari 断网时的 Range 请求异常。
